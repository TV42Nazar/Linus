# ЗВІТ ПРО ВИКОНАННЯ ПРОЄКТУ

**Тема:** Проєкти №14(база), №15(специфікація)

Варіант 15
---

## 1. Мета роботи

* **Дослідити механізм** створення та використання спільної пам'яті у стандартах POSIX для організації швидкого обміну даними між незалежними процесами.
* **Ознайомитися з проблемою** гонитви даних (Data Race) та засобами синхронізації процесів за допомогою іменованих POSIX-семафорів.
* **Набути практичних навичок** роботи із системними викликами низького рівня для керування пам'яттю та засобами синхронізації операційної системи Linux/UNIX.

---

## 2. Постановка завдання

1. **Розробити архітектуру обміну даними:**
Визначити єдину структуру даних для передачі телеметрії. Структура має містити показники датчиків: температуру, напругу, статус пристрою та текстове повідомлення.
2. **Програма-письменник (`writer`):**
Має ініціалізувати об'єкт спільної пам'яті, задавати його розмір відповідно до структури даних, відображати у свій адресний простір, записувати туди актуальну інформацію та за допомогою семафора сигналізувати про готовність.
3. **Програма-читач (`reader`):**
Має підключатися до створених об'єктів пам'яті та семафора, блокувати своє виконання до моменту отримання сигналу готовності, зчитувати дані, виводити їх на екран та коректно видаляти ресурси з операційної системи після завершення роботи.

---

## 3. Опис системних викликів та логіки роботи

Для реалізації взаємодії та синхронізації було використано класичний набір функцій POSIX API:

* **`shm_open`** — створює або відкриває об'єкт спільної пам'яті у віртуальній файловій системі ОС (повертає файловий дескриптор).
* **`ftruncate`** — встановлює фіксований розмір для виділеного об'єкта пам'яті, щоб він точно відповідав розміру нашої структури з даними.
* **`mmap`** — проектує (відображає) спільну пам'ять з дескриптора безпосередньо в адресний простір конкретного процесу. Це дозволяє працювати зі спільною пам'яттю як зі звичайною структурою в операційній системі.
* **`sem_open`** — створює або відкриває іменований семафор. Початкове значення встановлюється в `0`, завдяки чому читач гарантовано зупиниться на старті й чекатиме на письменника.
* **`sem_wait`** — зменшує значення семафора. Якщо семафор дорівнює `0`, процес-читач блокується (засинає), запобігаючи читанню порожньої або не повністю записаної пам'яті.
* **`sem_post`** — збільшує значення семафора на `1`. Цей виклик виконує письменник після завершення запису, що слугує сигналом («будильником») для читача.
* **`munmap` та `close**` — від'єднують пам'ять від адресного простору процесу та закривають дескриптори файлів.
* **`shm_unlink` та `sem_unlink**` — повністю видаляють об'єкти спільної пам'яті та семафора із системи (виконуються читачем наприкінці роботи).

---

## 4. Покрокова інструкція з компіляції та запуску

Для збирання та тестування програм у системі Linux необхідно використовувати термінал та компілятор `gcc`. Обов'язковою умовою є підключення системних бібліотек для роботи з реальним часом (`-lrt`) та потоками/семафорами (`-pthread`).

---

## 5. Висновки

Під час виконання лабораторної роботи було успішно досліджено механізм міжпроцесної взаємодії (IPC) через спільну пам'ять POSIX. Спільна пам'ять є найшвидшим способом передачі даних між процесами в UNIX-системах, оскільки обмін корисним навантаженням відбувається безпосередньо в ОЗП без додаткового копіювання даних через ядро операційної системи.

Додатково було розв'язано проблему асинхронності за допомогою POSIX-семафорів. Завдяки механізму блокування `sem_wait` та сигналізації `sem_post` вдалося повністю усунути стан гонитви даних (Data Race) і забезпечити гарантію того, що процес-споживач зчитує інформацію лише тоді, коли процес-виробник завершив її формування. Об'єкти після роботи були коректно видалені за допомогою функцій `unlink`, що запобігає витоку системних ресурсів (витоку пам'яті та дескрипторів).

1. **Компіляція вихідного коду:**
Скомпілюйте обидві програми за допомогою компілятора `gcc`.
```
gcc writer.c -o writer -lrt -pthread
gcc reader.c -o reader -lrt -pthread
./writer
./reader
```
